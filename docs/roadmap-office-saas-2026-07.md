## 티어 1 — 이미 80% 만들어진 것 완성 (몇 주, ROI 최고)

- [ ] **사무소 경비(office_expenses) 입력 UI** — 서비스 함수(CRUD)는 완성돼 있고 화면만 없음. 이것이 없어서 영업이익=매출, 손익·부가세 자료가 반쪽.
- [ ] **매입 거래(transactions) 수동 입력 UI** — 매입 생성 경로 자체가 0. 위와 동일한 이유로 세무 모듈 무력화 중.
- [ ] **기한 수정(edit)** — 지금은 생성·삭제만 되고 수정 불가.
- [ ] **서명 링크 문자 발송** — Solapi 인프라 있음. 지금은 링크 복사→수동 카톡.
- [ ] **케어 메시지 실제 발송(문자)** — AI 생성까지 되는데 발송 버튼이 없음. 알림톡은 티어 3.

## 티어 2 — 사무실 운영의 뼈대 (1~2달)

- [ ] **사건 실체 필드 추가** — 사건번호·관할법원·재판부·상대방·심급이 스키마에 없음. 사건관리 SaaS의 기본기.
- [ ] **의뢰인 CRM(라이트)** — 의뢰인 마스터 컬렉션 신설(연락처·복수 사건 연결). 지금은 clientName 문자열뿐이라 발송 기능들도 수신번호가 없다.
- [ ] **수동 사건 등록 폼** — 신규 가입 변호사는 진행 중 사건 수십 건을 들고 온다. 상담 플로우 없이 사건을 만들 수 없으면 이관 자체가 불가능.
- [ ] **통합 캘린더** — 전 사건 기한·기일 월간 뷰(/calendar). 사건 상세 안에서만 보이는 현재 구조로는 "오늘 뭐 있지"에 답을 못 함.
- [ ] **문서고(사건 횡단 문서 검색·목록)** — 문서가 사건별 서류철에만 갇혀 있음.
- [ ] ⚠ **기일 자동 동기화 재검토(대표 결정 필요)** — 2026-07-06에 직접 구현을 제거하고 외부 서비스(월 9,900원)로 대체하기로 결정했던 사안. 단, 시장 조사 결과 나의사건검색 자동동기화는 로웨어·Lawyers Plan 등이 전부 하는 관행 기술이며 공식 API 부재가 장벽이 아님이 확인됨. 결정 유지(외부 병용) vs 재구현 중 선택.

## 티어 3 — 차별화·성장 (분기)

- [ ] **성공보수 자동 청구 파이프라인** — 판결 확정 체크 → 승소간주 판단 보조 → 산정 → 청구서 생성 → 문자 발송 → 미수 추적. 시장 공백 1순위 + 성공보수 분쟁 빈발 영역.
- [ ] **의뢰인 포털(토큰 링크, 읽기 전용)** — 서명 페이지와 같은 방식으로 변호사가 초대. 진행상황·다음 기일·안내 메시지 열람. 아무도 안 하고 있음. B2B 정체성 유지(변호사가 주체).
- [ ] **알림톡 정식 도입** — 카카오 채널 + 템플릿 심사. 문자보다 도달·신뢰 우수.
- [ ] **백업·데이터 내보내기** — 사건·문서·녹음 일괄 반출. 변호사의 문서보관 의무 + "내 데이터 인질 아님" 신뢰 장치.
- [ ] **통계 리포트** — 상담→수임 전환율(상담 데이터를 이미 보유한 우리만 가능), 유형별 매출, 월 추이.
- [ ] **온보딩 투어** — 신규 가입 후 첫 사건 등록까지의 인앱 가이드.
