## 2. 이용 희망 API 및 활용 시나리오

### 2.1. 민사본안사건기본정보 (1순위)
- 사건번호 입력 → 당사자/법원/재판부/소가 자동 채움
- `docgen` 에이전트 서면 양식 정확도 향상
- `review` 에이전트가 사건번호/당사자 표기 대조 검증
- 실비계산기(`courtFeeCalculator.ts`)에 소가 자동 연동

### 2.2. 민사본안사건진행내역 (1순위)
- Timeline 자동 동기화 (현재 수동 입력)
- 기일/기한 자동 알림 (ScheduleTab.tsx)
- 의뢰인 카카오톡 메시지에 최신 진행상황 반영
- `analysis` 에이전트에 진행내역 제공 → 현재 단계 맞춤 전략

### 2.3. 기록뷰어기록목록 + 사건기록다운로드 (1순위, 킬러 피처)
- 상대방 서면 자동 감지 → OCR → 6개 에이전트 자동 실행 → 반박 준비서면 초안
- 업계 최초 기능 가능

```
기록목록 API 폴링 → 새 상대방 서면 감지
    ↓
기록다운로드 API → PDF 다운로드
    ↓
OCR(clova-ocr.ts) → 텍스트 추출
    ↓
6개 에이전트 자동 실행 → 반박 준비서면 초안
    ↓
변호사 알림: "상대방 준비서면이 제출됐습니다. 반박 초안을 생성했습니다."
```

### 2.4. 보정서 (2순위)
- 보정명령 감지 → 기한(14일) 자동 추적 → 보정서 자동 초안 생성
- 기한 도과로 인한 소 각하 방지

### 2.5. 판결문목록 + 판결문사건압축다운로드 (2순위)
- 판결문 AI 분석 → 승소/패소 요인 분석
- 항소 승소 가능성 평가 → 항소장/항소이유서 자동 초안
- RAG DB에 판결문 임베딩 → 유사 사건 검색 정확도 향상

### 2.6. 독촉사건 (기본정보 + 진행내역) (2순위)
- 지급명령 사건 관리 (소규모 사무소 주력 사건)
- 이의신청 감지 → 소장 전환 초안 자동 생성
- 이의신청 기간(2주) 만료 알림

### 2.7. 오픈 API(등기정보) (2순위)
- 부동산 등기부 자동 조회 → 가압류 신청서에 부동산 표시 자동 기재
- 법인 등기부 → 대표자/소재지 확인
- 근저당/가압류 현황 분석 → 채권 회수 가능성 평가

### 2.8. 회생파산사건정보 (3순위)
- 개인회생/파산 사건 관리
- 변제계획안 제출 기한 자동 추적

### 2.9. 사실조회회신 (3순위)
- 사실조회 결과를 증거로 자동 편입
- `analysis` 에이전트에 주입 → 유리/불리 증거 분류

### 2.10. 제3채무자진술서 (3순위)
- 채권압류 사건에서 추심 가능 금액 자동 파악

### 2.11. 기일입찰조서 / 현황조사보고서 (4순위)
- 경매 사건 특화, 현재 타겟과 거리

## 3. 에이전트별 법원 데이터 주입 계획

| 에이전트 | 주입 데이터 | 효과 |
|----------|------------|------|
| precedent(판례검색) | 사건유형/청구원인 | 검색 키워드 정밀화 |
| legal(적법성검증) | 진행내역, 보정서 | 절차적 적법성 실시간 검증 |
| analysis(쟁점분석) | 상대방 서면 전문 | 상대방 논리 약점 분석 |
| docgen(문서작성) | 사건기본정보, 등기정보 | 사건번호/당사자 자동 기재 |
| review(검토감수) | 사건기본정보 | 서면 내 오기 대조 검증 |

## 4. 기술 구현 계획

### 4.1. 프록시 구조
```
프론트엔드 → /api/scourt/* (Cloudflare Functions)
    → openapi.scourt.go.kr (API-KEY 헤더)
```
- functions/api/scourt/ 디렉토리에 API별 프록시 함수
- API-KEY는 Cloudflare Workers 시크릿 (SCOURT_API_KEY)

### 4.2. 서비스 모듈
- `src/services/scourt-api.ts` 신규 생성
- 각 API별 타입 정의 + 호출 함수 + 포맷팅 함수

### 4.3. AgentContext 타입 확장
```typescript
courtCaseInfo?: string;        // 민사본안사건기본정보
courtProgress?: string;        // 민사본안사건진행내역
opponentFilings?: string;      // 상대방 서면 텍스트
correctionOrder?: string;      // 보정서 내용
factInquiryResult?: string;    // 사실조회회신
registryInfo?: string;         // 등기정보
judgmentText?: string;          // 판결문 텍스트
```

### 4.4. Firestore 스키마 확장
```typescript
interface Case {
  // 기존 필드 + 추가
  courtCaseNumber?: string;     // 법원 사건번호
  courtName?: string;           // 관할 법원
  courtDivision?: string;       // 담당 재판부
  opposingParty?: string;       // 상대방
  claimAmount?: number;         // 소가/청구금액
  scourtSynced?: boolean;       // 포털 연동 여부
  scourtLastSync?: Timestamp;   // 마지막 동기화
}
```

### 4.5. 데이터 동기화
- 사건 진행내역: 매 2시간 폴링 또는 사용자 조회 시 갱신
- Firestore 캐시 → API 호출 최소화
- 변경 감지 시 알림 발송
