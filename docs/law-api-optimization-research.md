# 법제처 API 최적 활용법 연구

> 4개 에이전트 팀이 실제 API를 호출하여 검색 패턴, 데이터 품질, 문서 작성 활용법을 분석한 결과.

---

## 1. 판례 검색 (prec) 최적화

### 1.1 키워드 작성 규칙

| 어절 수 | 예시 | totalCnt | 품질 |
|---------|------|----------|------|
| 1어절 | "사기" | 2,842 | 낮음 — "재심사기각" 등 부분 매칭 노이즈 |
| **2어절** | **"사기 편취"** | **6** | **높음 — 정확히 적중** |
| 3어절 | "사기 편취 고의" | 0 | 결과 없음 (AND 조건) |

**규칙**: 반드시 **2어절**로 검색. 1어절은 노이즈, 3어절은 0건.

### 1.2 JO 파라미터 활용

| 패턴 | 결과 | 평가 |
|------|------|------|
| JO만 (JO=형법) | 10,392건 | 너무 넓음 |
| **JO+query (JO=형법, query=사기)** | **44건** | **최적** |
| query만 (query=사기) | 2,842건 | 노이즈 |

**규칙**: `JO=법률명` + `query=쟁점키워드` 조합이 가장 정밀.

### 1.3 display & sort

- **display=5** 기본, 부족하면 10. 20이면 노이즈 증가.
- **sort 생략** (기본이 최신순=ddes). 별도 지정 불필요.

### 1.4 상세 조회 필드별 활용 가치

| 필드 | 평균 길이 | 활용 | truncate 권장 |
|------|----------|------|--------------|
| **판시사항** | 613자 | 쟁점 목록 직접 인용 | **600자** (현재 800→축소 가능) |
| **판결요지** | 3,305자 | 법리 논증의 핵심 | **1,500자** (현재 1,000→상향 필수) |
| 판례내용 | 7,865자 | 대부분 절차적 내용 | **500자 또는 삭제** (현재 1,000→하향) |
| 참조조문 | 163자 | 법조문 매핑 검증 | **200자** (현재 300→충분) |
| 참조판례 | 210자 | Citation chaining | **250자** (현재 300→충분) |

> **핵심**: 판결요지 truncate를 1,000→1,500으로 올리고, 판례내용을 1,000→500으로 내려서 토큰 재배분.

## 2. 지능형 API 최적화

### 2.1 aiSearch vs aiRltLs

| 항목 | aiSearch | aiRltLs |
|------|----------|---------|
| 조문 원문 | **포함** | 없음 (제목만) |
| 검색 정확도 | 동일 | 동일 |
| 추가 API 호출 | 불필요 | 원문 필요시 추가 호출 |
| **평가** | **★★★★★** | ★★★☆☆ |

**결론**: aiSearch가 원스톱으로 우월. aiRltLs는 보조로만.

### 2.2 aiSearch display 최적값

| display | 건수 | 토큰 | 품질 |
|---------|------|------|------|
| 3 | 핵심 3건 | ~830 | 충분 (간단한 참조) |
| **5** | **핵심 + 보조** | **~1,180** | **가성비 최적** |
| 10 | 노이즈 포함 | ~2,640 | 7번째부터 무관한 결과 |

**규칙**: display=5 고정.

### 2.3 lstrmRltJo (법령용어-조문) 주의사항

| 키워드 | 품질 | 문제 |
|--------|------|------|
| "불법행위" | ★★★★ | 양호, 단 민법 제750조 누락 |
| "임대차" | ★★ | 농지법만 반환, 주택임대차보호법 누락 |
| "사기" | ★ | 동음이의어 오류 (사기=士氣로 매칭) |

**규칙**: 동음이의어 위험이 있는 키워드는 lstrmRltJo 사용 지양, aiSearch로 대체.

## 3. 참조판례 체인 추적 (Citation Chaining)

### 3.1 검증 결과

```
의료과실: 키워드검색(2021도1833) → 참조판례(2010도14102) → 참조판례(95도2710, 1996년 리딩케이스)
부당해고: 키워드검색(2023두54914) → 참조판례(2004다29736, 2000두8455, 원조 판례들)
```

**키워드 검색만으로는 도달 불가능한 1990년대 리딩케이스까지 추적 성공.**

### 3.2 참조판례 필드 형식

```
"대법원 2011. 4. 28. 선고 2010도14102 판결, 대법원 2023. 1. 12. 선고 2022도11163 판결"
```

사건번호 추출 정규식:
```javascript
/(\d{2,4}[다도두부나마카타바사아자차파하]\d+)/g
```

평균 참조판례: 2~5건. 리딩케이스(원조)에 가까울수록 0~1건.

### 3.3 구현 시 주의

- 사건번호로 재검색 시 원본이 아닌 **해당 판례를 인용한 후속 판례**가 나올 수 있음
- 검색 결과에서 `사건번호`가 정확히 일치하는 것만 필터링 필요
- **최대 깊이 2~3홉** (무한루프 방지)

## 4. 법령해석례 (expc) 심층 활용

### 4.1 현재 문제

검색(lawSearch)만 하고 **상세 조회(lawService)를 하지 않음** → 질의요지/회답/이유 분리 데이터 미활용.

### 4.2 상세 조회 필드

| 필드 | 길이 | 활용 |
|------|------|------|
| **회답** | ~148자 | 공식 결론. 짧고 명확. 프롬프트 효율 최고 |
| **질의요지** | ~145자 | 쟁점 프레이밍 |
| **이유** | ~1,366자 | 상세 논증. 판례 인용 포함 |

**규칙**: 상위 1~2건 상세 조회 추가 → 회답+질의요지만 주입 (토큰 효율적).

## 5. 노동위원회 (nlrc) 활용

- **38,392건** 데이터풀
- 상세 조회 시 판정사항+판정요지 제공 (전문은 미제공)
- 판정요지 ~300자, 핵심 논점 간결
- **부당해고 사건에서 유사 판정례로 활용 가치 높음**

## 6. 에이전트별 최적 조합 (최종 권장)

### 한판서 (판례 검색)

```
1. prec 키워드 검색 (query=2어절, display=5)
2. prec 상세 조회 (상위 3~5건, 판시사항+판결요지+참조조문+참조판례)
3. detc 헌재결정례 (query=키워드, display=2)
4. [노동] nlrc 심판례 (사건 유형이 노동일 때)
5. [공정거래] ftc 심결 (사건 내용에 공정거래 포함 시)
```

### 서혜안 (쟁점 분석)

```
1. aiSearch 지능형 검색 (query=키워드, display=5) — 조문 원문 확보
2. aiRltLs 연관법령 (query=키워드, display=5) — 관련 조문 목록 (10→5 축소)
3. lstrmRltJo 사용 조건부 — 동음이의어 위험 없는 키워드만
```

### 윤율무 (적법성 검증)

```
1. expc 검색 (query=키워드, display=3)
2. expc 상세 조회 (상위 1~2건) — 질의요지+회답 확보 (신규 추가)
3. aiSearch 조문 원문 (query=키워드, display=3) (신규 추가)
```
