# LAW-CADDY 재무 관리 모듈 리서치 보고서

> 작성일: 2026-04-11
> 대상: LAW-CADDY 프로덕트/엔지니어링 팀
> 범위: 1~5인 소규모 법률사무소(특히 1인 변호사)를 위한 재무 관리 기능 설계
> 전제: 세무 신고는 외부 회계사무소 대행, LAW-CADDY는 "회계사에 넘기기 전 단계"의 기록·집계·증빙 관리를 담당한다.

## TL;DR (핵심 5줄 요약)

1. **코드베이스에 이미 골격이 존재한다.** `src/types/accounting.ts`(635줄)와 `src/pages/FinancePage.tsx`(1,031줄)에 Fees / Transactions / OfficeExpenses / Deposits / MonthlySummary 6개 컬렉션 스키마가 정의되어 있고 대시보드·월간리포트·세무리포트·자동연동 4탭 UI까지 있다. 본 리서치의 MVP 제안은 **"새로 만드는 것"이 아니라 "이 골격을 실데이터로 동작시키고 UX를 단순화"하는 방향**이다.
2. **1인 변호사의 진짜 Pain은 "세무 지식 부족 + 월말 몰아치기"이다.** 영수증 사진 한 장 → 자동 분류 → 월말에 회계사에게 엑셀 한 방이 되는 워크플로우가 전부다. 복잡한 ERP식 부기는 반감만 산다.
3. **변호사 특유 Must-Have는 세 가지다.** (a) **예수금/보관금**을 본인 수입과 완전히 분리(신탁계좌 개념), (b) **수임료를 착수금/잔금/성공보수로 분리 + 미수금 추적**, (c) **사건(`cases`)과 수입·지출의 1:N 연동** — 이 셋은 삼쩜삼·자비스 같은 범용 앱이 절대 못 풀어주는 변호사만의 요구.
4. **경쟁 구도상 LAW-CADDY의 위치는 "변호사 특화 얇은 장부 + 회계사 다리 역할"이다.** Clio($49~$149/mo)는 한국 세법 미지원이고, 자비스/삼쩜삼은 변호사 도메인 지식 없음. **₩89,000/월 Pro 요금에 재무 모듈을 "공짜 번들"로 포함**시키면 가격 경쟁력 + 락인 효과가 동시에 생긴다.
5. **MVP는 4~6주면 출시 가능하다.** Phase 1 핵심: ① 영수증 사진 업로드+CLOVA OCR 자동 분류, ② 사건 상세 페이지에서 수임료/실비 1-클릭 입력, ③ 월말 "회계사에게 보낼 엑셀" 원클릭 내보내기 + 카카오톡/이메일 공유. 나머지(홈택스 연동, 자동 매칭, 리포트 AI 해석)는 Phase 2+로 미룬다.

## 1. 1인 변호사의 재무 관리 실태 (한국 기준)

> 본 섹션은 업계 통상 및 공개 블로그·법률 커뮤니티·세무사 콘텐츠에서 반복되는 이슈를 종합한 **관찰 기반 추정**이며, 정밀 서베이 수치는 아님.

### 1.1 현재 관행 (추정상)
- **엑셀 + 카카오톡 사진 보관**이 가장 흔한 패턴. 의뢰인별 수임료는 엑셀 한 시트, 영수증은 휴대폰 갤러리 "회계" 앨범 혹은 본인과의 카카오톡.
- **통장 입출금 내역이 사실상 장부.** 월말에 은행 앱 거래내역을 PDF/엑셀로 받아 회계사에 전달.
- **신용카드 명세서 의존도가 높다.** 사무실 전용 카드를 따로 만들어 업무 경비로 몰아 쓰고, 명세서를 그대로 넘긴다.
- **회계사에 "월 기장료 10만~20만원"** 지급하는 구조가 많고, 회계사가 자비스/더존 등으로 자체 입력. 변호사 본인은 영수증만 취합.

### 1.2 빈번한 Pain Point
| # | Pain | 심각도 | 비고 |
|---|------|--------|------|
| P1 | **영수증 분실/중복** — 커피숍 영수증, 법원 인지대 납부 영수증이 뒤섞임 | 상 | MVP 1순위 타깃 |
| P2 | **수임료 미수 관리 부실** — 착수금은 받았는데 잔금·성공보수 청구 시점을 놓침 | 상 | 변호사 특유 |
| P3 | **예납금과 본인 수입의 혼동** — 의뢰인 돈으로 인지대 납부 후 본인 통장에서 집행, 나중에 구분 어려움 | 상 | 윤리·법적 리스크 포함 |
| P4 | **사적 지출과 업무 지출이 같은 카드/계좌** — 경비 처리 누락 또는 과다 | 중 | |
| P5 | **세무신고 직전(5월) 1년치 벼락치기** — 회계사가 빠진 영수증 요청해도 못 찾음 | 상 | 연 1회 대참사 |
| P6 | **부가세 분기 신고 마감을 기억 못 함** (1/25, 4/25, 7/25, 10/25) | 중 | 알림만 있어도 해결 |
| P7 | **의뢰인 실비(교통비·등기부등본) 정산 요청 타이밍 놓침** | 중 | 사건 종료 시 일괄 |
| P8 | **월 손익을 모름** — "이번 달 얼마 벌었지?" 에 즉답 불가 | 중 | 감정적 만족도 영향 |

### 1.3 시사점
- **"회계를 잘하고 싶다"가 아니라 "회계 때문에 스트레스 받기 싫다"가 실질 니즈.** 기능이 많을수록 오히려 도망간다.
- **카카오톡에서 벗어나지 못한다.** 월말 보고서를 "카톡으로 회계사에 쏠 수 있는 PDF/링크 1개"로 만들어야 한다.
- **"자동"이 최강 구매 동기.** 카드 명세서 자동 파싱 > 수동 입력 폼 10개.

## 2. 한국 세무·회계 규정 (변호사 특화)

> 업계 통상 정보 + 공식 문서(국세청, 법제처, 볼타/택슬리/토스페이먼츠 블로그) 기준. 2026-04-11 현재 유효.

### 2.1 변호사의 사업자 유형
- 변호사는 **개인사업자(일반과세자)** 또는 **법무법인(법인사업자)** 형태가 일반적. 1인 변호사는 거의 개인·일반과세자.
- **간이과세 불가**: 변호사·회계사·세무사 등 전문직은 간이과세 배제 업종이므로 매출 규모와 무관하게 일반과세자다. *(공식: 부가가치세법 시행령 제109조)*
- **면세**: 변호사 용역은 과세 대상(부가세 10% 부과).

### 2.2 부가가치세 (VAT)
- **세율 10%** (용역 공급가액 기준).
- **신고 주기** (개인사업자 기준):
  | 신고 구분 | 과세기간 | 신고·납부 기한 |
  |---|---|---|
  | 1기 예정 고지 | 1~3월 | 4월 25일 (고지분 납부) |
  | 1기 확정 | 1~6월 | 7월 25일 |
  | 2기 예정 고지 | 7~9월 | 10월 25일 (고지분 납부) |
  | 2기 확정 | 7~12월 | 다음 해 1월 25일 |

  *개인사업자는 예정 신고 대신 직전 세액 1/2 고지가 원칙. 확정 신고 시 정산.* *(출처: 볼타 "2026년 부가세 신고 기간 총정리")*

- **전자세금계산서 의무 발행**: 직전 연도 **과세 공급가액 8,000만원 이상**이면 의무. (법인은 금액 무관 의무.) 미발행 2%, 종이 발행 1% 가산세. *(출처: 볼타/행복한하하네)*
- **현금영수증 의무 발행**: 변호사업은 현금영수증 **의무 발행 업종**이며, 건당 10만원 이상 거래를 현금으로 받으면 상대방 요청이 없어도 의무 발행.

### 2.3 종합소득세
- **5월 1일~5월 31일** 전년도 사업소득 신고(성실신고확인 대상자는 6월 30일).
- 1인 변호사의 경우 직전 연도 수입금액에 따라 **복식부기 의무자 vs 간편장부 대상자** 구분. 변호사는 전문직이므로 **수입금액 무관하게 복식부기 의무자**다. *(소득세법 제160조, 시행령 제208조: 전문직 사업자는 무조건 복식부기)*
- 따라서 실제로는 **회계사무소 기장 대행이 사실상 필수**다. 이 점이 "LAW-CADDY는 회계사 대체가 아니라 회계사에게 잘 넘기는 도구"라는 포지셔닝의 근거.

### 2.4 원천징수
- **지급 측(보내는 측)의 의무:**
  - 변호사가 프리랜서(사무보조, 번역가 등)에 대가 지급 시 **사업소득 3.3% 원천징수** 후 다음 달 10일까지 신고·납부. *(출처: 국세청 "원천징수 대상 사업소득")*
  - 직원 급여 → 근로소득 간이세액표 기준.
- **수취 측(받는 측)의 경우:** 의뢰인이 **법인**이거나 **개인사업자(원천징수 의무자)**일 때는 변호사 수임료에서 **3.3%를 차감하고 입금**. 이 금액은 5월 종소세 신고 시 기납부세액으로 공제.
  - → 시스템상 **"입금액 ≠ 약정 수임료"**가 빈번. 차액 관리 기능 필요.

### 2.5 복식부기 / 간편장부 (요약)
| 구분 | 대상 | 비고 |
|---|---|---|
| 복식부기 의무자 | **전문직(변호사 포함)은 전원** | 외부 기장 사실상 필수 |
| 간편장부 대상자 | 해당 없음 (변호사) | — |

### 2.6 LAW-CADDY 구현 시 체크리스트
- [ ] 공급가액(부가세 제외) / 부가세 / 합계금액 **3필드로 저장**. (이미 `VatInfo` 타입 있음)
- [ ] 전자세금계산서 발행 여부 플래그 + 국세청 전송 여부 플래그. (이미 `TaxInvoiceInfo` 있음)
- [ ] 현금영수증 승인번호 저장 필드. (이미 `CashReceiptInfo` 있음)
- [ ] 의뢰인 유형(개인/법인)에 따라 3.3% 원천징수 자동 계산 — **현재 미구현, 추가 필요**.
- [ ] 부가세 1/4/7/10월 25일 자동 알림 — **현재 미구현**.
- [ ] 5월 종소세 시즌 특별 모드 — **현재 미구현**.

## 3. 변호사 특유의 재무 이슈

### 3.1 수임료 구조의 3단 분리
변호사 수임료는 단일 금액이 아니다. **세 시점**에 발생한다.
1. **착수금(retainer)** — 수임 계약 체결 시 선납. 받는 즉시 매출 인식.
2. **중간보수/잔금** — 사건 진행 단계별 또는 1심 판결 후. 분할 납부가 흔함.
3. **성공보수(success fee)** — 판결 확정 또는 합의 성립 시. 비율형(승소금액의 N%) 또는 정액형.

**설계 시사점:**
- 한 사건당 `Fee` 1건, 그 안에 retainer / balance / successFee 3 sub-object + installments[] 서브컬렉션.
- `totalAgreedAmount`(약정 총액) vs `totalPaidAmount`(실제 입금) 상시 계산. 차액이 미수금.
- 현재 `accounting.ts`의 `Fee` 인터페이스가 이미 이 구조를 반영하고 있음. **수정 불필요.**

### 3.2 예납금/보관금 (Trust / Client Funds) — 최고 난이도 이슈
- 의뢰인에게 받은 **인지대/송달료/감정료 등 소송비용 대납용 선납금**은 법적으로 **변호사의 수입이 아니다.**
- 그러나 실제로는 변호사 개인 계좌로 입금받고 개인 카드로 법원 납부하는 관행이 만연. **분리 관리 실패 → 횡령 사고** 보도 다수.
- 한국은 아직 **미국 IOLTA같은 의무 신탁계좌 제도가 법제화되지 않았지만** 대한변협 차원에서 도입 논의 중. *(출처: 한국법학원 "변호사 신탁계좌에 관한 연구")*

**설계 시사점:**
- `deposits` 컬렉션을 **회계상 "내 매출/지출"과 완전히 격리**해 집계해야 한다. 현재 스키마는 이미 이렇게 설계됨.
- 대시보드 상단에 "보관 중 예수금: ₩X,XXX,XXX" **상시 표시** → 변호사 본인도 경각심.
- 사용 내역(`DepositUsage[]`)을 사건비용(`CaseExpense`)과 자동 연결.
- **Phase 2 기능 아이디어:** 예수금 전용 통장 계좌번호 등록 → 입출금 자동 매칭.

### 3.3 실비 정산 (Reimbursement)
- 변호사가 **선(先) 납부 후 의뢰인에게 청구**하는 경우가 많다: 등기부등본·주민등록초본 발급비, 교통비, 복사비.
- 누락되면 수백만원도 쉽게 증발. 사건 종료 시 일괄 정산이 일반적.
- `CaseExpense.bearer = "선납후정산"` + `reimbursed` 플래그로 관리. (이미 구현됨)

### 3.4 고정 지출 (1인 변호사 평균 구성)
| 항목 | 월 평균 추정 | 비고 |
|---|---|---|
| 사무실 임대료 (서울 기준) | 80만~200만원 | 공유오피스는 30만~60만원 |
| 대한변협 + 지방변호사회 회비 | 약 3만~5만원 환산 | 분기납부 |
| 변호사 배상책임보험 | 연 30만~100만원 → 월 환산 3만~8만원 | 의무는 아니나 권장 |
| 법률 DB 구독 (로앤비, 엘박스 등) | 5만~20만원 | |
| 통신/인터넷 | 5만~10만원 | |
| 회계사 기장료 | 10만~25만원 | |
| **합계 (저가 케이스)** | **약 55만~150만원** | |

→ **고정비 경고 기능**: 어느 달 매출 < 고정비면 대시보드에 적색 경고.

### 3.5 미수금·분쟁
- 의뢰인 파산·잠적으로 인한 미수는 사건 종료 후 평균 5~15% 발생(업계 통상).
- **연체 N일 경과 시 알림** 기능이 Phase 2에 필요.

| 기존 cases 연동? | **사건 상세 페이지에 "재무" 탭 추가** | 가장 강력한 UX, 이미 구조 존재 |

### 4.2 MVP에서 **빼야 할 것** (함정)
- ❌ 복식부기 원장 자동 생성 → 회계사 영역. 손대지 말 것.
- ❌ 국세청 홈택스 직접 신고 → 규제 복잡, 인증서 필요.
- ❌ 은행 계좌 자동 스크래핑 → CODEF/팝빌 유료 API 의존, 신뢰성·법률 리스크.
- ❌ 급여·4대보험 계산 → 1인 변호사 대부분 직원 없음.
- ❌ 세금 계산기·절세 시뮬레이터 → 오해 시 배상 리스크.

- **한국 1인 변호사용으로 "재무 모듈까지 포함된 올인원 SaaS"는 사실상 빈 시장이다.**

## 6. 회계사무소와의 연동 시나리오

### 6.1 일반적 월말 워크플로우 (관찰 기반)
```
D+0 (월말)
  변호사 → 회계사: 카카오톡으로 영수증 사진 + 엑셀(수입·지출) 전달
D+5
  회계사: 자비스/더존/위하고에 입력
D+10
  회계사: 빠진 영수증 요청 ("OO식당 카드 매출 전표 있나요?")
  변호사: 카드사 앱에서 찾아서 캡처 재전송 (지옥)
```

### 6.2 회계사가 선호하는 포맷
1. **엑셀(.xlsx)** — 압도적 1위. 날짜/적요/금액/카테고리/증빙번호 5~7열.
2. **PDF 요약 리포트** — 월간 손익 개요용 보조.
3. **증빙 파일 zip** — 영수증 사진 묶음.
4. **카카오톡 / 이메일** 전달 — 드라이브 공유는 회계사가 선호하지 않음(반복 다운로드 번거로움).

### 6.3 LAW-CADDY가 제공할 "회계사 친화" 기능
- **"월별 리포트" 탭에서 원클릭 "회계사에게 보내기"** 버튼:
  1. 해당 월 Transactions + OfficeExpenses + CaseExpenses + Fees(입금분) 엑셀 1개 생성
  2. Attachments zip (영수증·세금계산서 파일)
  3. 회계사 이메일(설정에 저장) 자동 수신자
  4. 발송 로그 기록 (`MonthlySummary.sentToAccountant`, `sentAt`)
- **"회계사 초대" 기능 (Phase 2):** 회계사 이메일로 읽기 전용 링크 발송. 월별 요약을 웹에서 바로 열람.
- **"미비 증빙 경고"**: 증빙 없는 거래 건수를 `evidence.noEvidenceCount`로 집계, 월 마감 전에 배지로 경고.

## 7. LAW-CADDY 통합 전략 (Phase 1 → 3)

### Phase 1 — MVP (4~6주 안 출시 가능)

**목표:** "회계사에게 월말 엑셀 한 방" 워크플로우 완성.

**기능:**
1. **사건 상세 페이지 > 재무 탭** — 수임료(착수금/잔금/성공보수) 입력, 입금 처리, 사건비용 입력
2. **영수증 업로드** — 사진 → CLOVA OCR 영수증 모델 → 카테고리 자동 추정 → 수동 확인/수정 → 저장
3. **월별 리포트 탭** (이미 있음, 실데이터 연결)
4. **회계사 엑셀 원클릭 내보내기** (xlsx + 증빙 zip)
5. **대시보드 상단 위젯**: 이번 달 매출, 이번 달 지출, 미수금, 보관 중 예수금, 부가세 다음 마감일 카운트다운
6. **고정비 반복 등록** (OfficeExpense.recurring) — 임대료·회비 1회 등록 → 매월 자동 생성
7. **증빙 없는 거래 경고 배지**

**DB 스키마 (Firestore):** 이미 존재하는 `accounting.ts` 사용. 변경 없음.

**UI 페이지:**
- `/finance` (기존 FinancePage — 실데이터 바인딩만)
- `/cases/:id` 에 `FinanceTab` 서브 탭 **추가**
- 대시보드에 `FinanceWidget` **추가**

**외부 API/SDK:**
- **네이버 CLOVA OCR 영수증 전용 모델** — 300건/18,000원, 이후 건당 100원. 월 300건이면 MVP 충분. `src/services/clova-ocr.ts` 이미 존재 → 영수증 엔드포인트 추가.
- **ExcelJS** (클라이언트) 또는 `src/services/excelExport.ts` 기존 활용.

**예상 개발 공수:** 프론트 3주 + 백엔드/Firestore 1주 + OCR/Export 1주 + QA 1주 = **6주**.

### Phase 2 — 자동화·효율화 (3개월 내)

1. **카드 명세서 CSV 업로드 → 자동 분류** (카테고리 학습)
2. **부가세·종소세 마감 알림** (이메일 + 카카오톡 알림톡)
3. **미수금 자동 알림** — 약정일 + N일 경과 시 의뢰인 메시지 초안 생성 (기존 의뢰인 메시지 기능과 연동)
4. **회계사 읽기 전용 포털** — 토큰 기반 공유 링크
5. **분기별 / 연간 리포트** 집계
6. **예수금 입출금 내역 입력 UI** 강화, 사건비용과 자동 연결
7. **사건 종료 시 실비 일괄 정산 청구서 생성**
8. **홈택스 전자세금계산서 발행 대행** (팝빌·링크허브 API 연동) — 부가세 의무 8,000만원 이상 변호사 대상

**외부 API:**
- **팝빌 홈택스 수집 API** (월 구독, 대략 건당 과금) — 전자세금계산서·현금영수증 매입/매출 자동 수집
- **카카오 알림톡** (비즈메시지) — 마감 알림
- **SendGrid / SES** — 월간 리포트 이메일 발송

### Phase 3 — 인사이트·AI (6개월+)

1. **AI 재무 어드바이저** (Claude Sonnet) — "이번 달 접대비가 평소보다 40% 많네요, 확인해보세요" 같은 월간 코멘터리
2. **사건별 ROI 분석** — 투입 시간 × 시간당 가치 vs 실제 수임료

## 12. 권장안 (Recommendation) & Action Items

### 12.1 권장안 요약

1. **"새 모듈을 만든다"보다 "기존 골격을 완성한다"가 정답이다.** `accounting.ts`와 `FinancePage.tsx`는 설계 품질이 이미 매우 높다. DEMO 데이터 → 실데이터 바인딩, OCR 입력 UI, 사건 연동 3가지만 붙이면 MVP가 나온다.
2. **포지셔닝은 "회계사 대체"가 절대 아니다.** "회계사에게 월말 엑셀 한 방"이 구호. 변호사가 복식부기 의무자라는 사실이 오히려 기회: 직접 기장하려는 시도를 막고 LAW-CADDY를 "중간 정리 도구"로 납득시키기 쉽다.
3. **가격 정책: Pro(₩89,000/월)에 재무 모듈 기본 포함.** 별도 과금 시 기장료 대비 가격 저항 발생. 재무는 락인 기능이고 녹음·문서 생성은 획득 기능.
4. **3가지 차별화 기능을 잊지 말 것:**
   - (a) 수임료 3단 분리(착수/잔금/성공보수)
   - (b) 예수금 완전 분리 표시
   - (c) 사건(`cases`)과 재무의 1:N 연동
   이 세 가지는 삼쩜삼·자비스가 죽었다 깨나도 못 만든다.
5. **Phase 2 홈택스 연동 시 팝빌/링크허브가 현실적 선택지.** 국세청 공식 OpenAPI는 인증서·보안 장벽이 높다. CODEF도 선택지이나 스크래핑 기반 리스크가 있다.
6. **CLOVA OCR 영수증 모델이 가격·성능 모두 현 시점 최적.** 한국어 영수증 인식은 클로바가 구글보다 우세. 300건/18,000원으로 MVP 안정 운영 가능.
