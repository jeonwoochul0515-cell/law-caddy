## 1. 핵심 진단: 왜 매번 실패했는가

### 1.1 실패 이력 (6회 시도)

| 시기 | 시도 | 결과 | 근본 원인 |
|------|------|------|-----------|
| 2025-12 | 최초 판례 검색 구현 | 0건 반환, Claude가 판례 환각 | 에러 핸들링 없음, 타임아웃 없음 |
| 2026-01 | [검증필요] 티어 추가 | Claude가 여전히 가짜 판례 생성 | 증상 치료, 근본 원인 미해결 |
| 2026-03-18 | 환각 차단 (AI 지식 사용 금지) | "추가 검색 필요" 메시지만 반환 | 검색 자체가 0건인 문제 미해결 |
| 2026-03-23 | 타임아웃 15초 + 2회 재시도 | API 호출은 성공, 여전히 0건 | 검색 파라미터 문제 미해결 |
| 2026-04-01 | 순차 처리 + 300ms 딜레이 | API 안정화, 여전히 0건 | RAG 임계값 + ts_rank 버그 미해결 |

### 1.2 현재 시스템의 3가지 근본 원인

**근본 원인 #1: 법조문 기반 검색을 하지 않음**
- 변호사가 판례를 찾는 방법: 관련 조문 특정 → 그 조문을 해석한 판례 검색
- 현재 한판서: 키워드만으로 검색 ("손해배상"으로 9,307건 나열)
- 법제처 API의 `JO` 파라미터(법률명 필터)를 전혀 사용하지 않음

**근본 원인 #2: 참조판례 체인 추적(Citation Chaining) 미사용**
- API 테스트 결과, 가장 효과적인 전략은 **상세 조회 → 참조판례 필드 → 연쇄 추적**
- 예: 의료과실 사건에서 2022다264434 상세 조회 → 참조판례 5건(91다23707, 2002다45185 등) 자동 발견
- 현재 시스템은 상세 조회를 하지만 **참조판례 필드를 활용하지 않음**

**근본 원인 #3: RAG 41만건 판례 DB를 한판서가 사용하지 않음**
- Supabase에 41만건 판례 + Voyage 임베딩 인프라가 존재
- Stage 1에서 RAG 검색이 실행되지만, Stage 2 한판서에는 **전달되지 않음**
- 시맨틱 유사도 기반 판례 발견 기회를 완전히 놓치고 있음

## 2. API 실전 테스트 결과 (6개 가상 케이스)

### 2.1 법제처 API 동작 확인

| 항목 | 결과 |
|------|------|
| API 응답 속도 | 빠름 (1-3초) |
| Rate Limiting | 감지 안 됨 (헤더 없음) |
| 최대 display | 200건 (테스트 확인) |
| JO 파라미터 | **작동함** — 법률명 필터링 (단, 조문 번호는 무시됨) |
| nb 파라미터 | **작동함** — 사건번호로 직접 검색 |
| JO + query 조합 | **가장 효과적** — 민법+손해배상 → 501건 (민법만 21,520건) |
| org=400201 (대법원) | 작동하나 불안정, 미사용 권장 |

### 2.2 JO 파라미터 핵심 발견

```
JO=민법          → 21,520건 (민법 참조 판례 전체)
JO=형법          → 10,392건
JO=근로기준법     → 3,087건
JO=주택임대차보호법 → 315건
JO=민법 + query=손해배상 → 501건 (가장 유용한 조합)
```

**중요**: JO는 법률명만 필터링. `JO=민법 제750조`로 검색해도 `JO=민법`과 동일 결과(조문 번호 무시됨).
→ 특정 조문 판례를 찾으려면: `JO=민법` + `query=제750조` 조합 또는 상세 조회 후 참조조문 필드에서 필터링.

### 2.3 6개 케이스 테스트 결과

| 케이스 | 최적 키워드 | 결과 수 | 리딩케이스 발견 | 참조판례 체인 |
|--------|-------------|---------|----------------|--------------|
| 의료과실 손해배상 | `의료과실` | 19건 | 2022다264434 | 5건 추가 발견 |
| 사기죄 변호 | `편취` | 12건 | 2012도14516 | 3건 추가 발견 |
| 부당해고 | `부당해고` | 400건 | 2018두44647 | 4건 추가 발견 |
| 임대차보증금 | `임대차보증금 반환` | 31건 | 2024다326398 | 다수 |
| 이혼·재산분할 | `이혼 재산분할 위자료` | 10건 | 2025므10716 | 전원합의체 3건 |
| 영업정지 취소 | `영업정지처분 취소` | 128건 | 2023두57142 | 2건 추가 |

### 2.4 테스트에서 발견된 검색 규칙

1. **단일 정확 키워드가 최적** — "편취"(12건) > "사기죄 편취 고의"(0건)
2. **사건명(evtNm) 기반 검색** — 법리 용어(비례원칙, 재량권)는 사건명에 없어서 0건
3. **참조판례 체인 추적이 핵심** — 1건의 상세 조회로 리딩케이스 3~5건 추가 발견
4. **JO + query 조합이 가장 정밀** — 법률명으로 범위 축소 후 키워드로 특정
5. **org 파라미터 불안정** — 사용하지 않는 것이 안전 (대법원 판례는 기본적으로 상위에 나옴)

### Phase 2: 검색 엔진 3-Source 병합 (핵심 개선)

#### 2-A. 법제처 API JO 파라미터 검색 추가

`precedent-api.ts`에 새 함수 추가:

`precedent-search.ts` (Cloudflare proxy)에 JO 파라미터 전달 로직 추가.

#### 2-B. 참조판례 체인 추적 (Citation Chaining) 구현

`useAgents.ts` Stage 2에 추가:

```typescript
// 상위 판례의 참조판례 필드에서 사건번호 추출 → 추가 상세 조회
for (const prec of topPrecedents) {
  if (prec.refCases) {
    const refCaseNumbers = extractCaseNumbers(prec.refCases);
    for (const refNum of refCaseNumbers.slice(0, 3)) {
      // nb 파라미터로 참조판례 검색
      const refResults = await searchByCaseNumber(refNum);
      // 상세 조회 → 리딩케이스 후보에 추가
    }
  }
}
```

**왜 이것이 게임체인저인가**: 
- 테스트에서 1건의 상세 조회만으로 해당 분야 리딩케이스 3~5건이 자동 발견됨
- 키워드 검색으로는 찾을 수 없는 1990년대 원조 판례까지 도달 가능
- 법률 실무에서 변호사가 사용하는 "판례 추적" 방법과 동일

#### 2-C. RAG 시맨틱 검색을 Stage 2에 연결

#### 2-D. 3-Source 결과 병합 & 중복 제거

```
Source A: JO 파라미터 법조문 검색 → 10건
Source B: 키워드 검색 (현재 방식) → 15건
Source C: RAG 시맨틱 검색 → 3건
Source D: 참조판례 체인 추적 → 5건

    ↓

    ↓

```

## 8. 핵심 결론

> **이전의 모든 실패는 "검색 엔진 자체"가 아니라 "검색 전략"의 문제였다.**
> 법제처 API는 정상 작동한다. 문제는 변호사가 판례를 찾는 방식(법조문→판례→참조판례 체인)을 시스템이 따르지 않았다는 것이다.

이번 계획의 핵심 차이점:
1. **실제 API 테스트로 검증됨** — 6개 케이스에서 JO 파라미터, 키워드, 참조판례 체인을 모두 테스트
2. **법률 실무 워크플로우 반영** — 법조문→판례→체인 추적은 변호사의 실제 검색 방법
3. **참조판례 체인 추적** — 1건의 상세 조회로 리딩케이스 3~5건 자동 발견 (테스트 검증 완료)
