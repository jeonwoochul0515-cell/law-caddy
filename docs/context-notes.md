## 2026-09-11 예행연습(2회 루프) → 전부 수정

- 지시 원문. "예행연습 스킬을 써줘 2번" → 보고 후 "전부다 고쳐줘".
- 사람. 부산 1인 사무소 40대 후반 변호사 김 변호사(개발 모름). 2차에서 사무직원 이 실장·의뢰인 박 사장 관점 추가.
- 진행 방식. 1차 8영역 + 2차 6관점 점검 14건(읽기 전용 에이전트) → 253건. 상위 20여 건은 메인 세션에서 코드로 재확인.
  수정은 파일 소유를 겹치지 않게 7개 흐름(가입·관리자 / 녹음·분석 / 문서·서명·포털 / 사건·일정 / 재무·결제 / 서버·규칙 / 공개화면·대시보드·문구)으로 나눠 병렬 진행. 에이전트는 커밋·빌드·배포 금지, 메인 세션이 흐름별로 빌드·테스트·커밋.
- 규칙에서 확인한 것. storage.rules의 `allow write`가 `request.resource.size`를 참조해 삭제가 항상 거부됨(delete엔 request.resource 없음) → read/create/update/delete로 분리 필요. `receipts/` 경로 규칙 없음. users 규칙이 생성 시 approved·자기 갱신 pending→approved 허용.
- 서버 한도(plan.ts)가 documents·cases 건수만 세어 직접 호출 시 무제한, 정상 흐름에선 마지막 1건이 막히는 off-by-one.
- 추가 지시(2026-09-11). 모두 수정한 뒤 예행연습을 한 번 더 돌리고, 그다음 호객꾼(상담 챗봇)을 설치한다.
- 결정. 판례 원문 링크·법정기간 계산·문서 판본·팀 계정 같은 설계 규모 항목은 "뒤로"로 표시하고 이유를 체크리스트에 적는다.
